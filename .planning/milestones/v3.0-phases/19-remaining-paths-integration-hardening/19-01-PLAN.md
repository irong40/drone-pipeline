**n8n/manual_path_workflow.json** — A single shared n8n sub-workflow JSON for both Path B (construction) and Path D (ADIAT). Follow the exact JSON structure from path_e_workflow.json. The workflow must:

1. Accept parameters from Package Router Execute Sub Workflow node: `{ mission_id, package_type, mission_number, folder_path }`
2. **Node 1 — "Set Manual Status"**: HTTP Request node that PATCHes the Supabase processing_jobs table, setting status to "manual" for the given mission_id. Use `{{ $env.SUPABASE_URL }}/rest/v1/processing_jobs?mission_id=eq.{{ $json.mission_id }}` with PATCH method. Headers: apikey and Authorization Bearer from `{{ $env.SUPABASE_SERVICE_KEY }}`. Body: `{"status": "manual", "updated_at": "now()"}`.
3. **Node 2 — "Notify Operator"**: Send Email node (type: `n8n-nodes-base.emailSend`). Recipient: `{{ $env.OPERATOR_EMAIL }}`. Subject: `[Sentinel] Manual Processing Required — Mission {{ $json.mission_number }} ({{ $json.package_type }})`. Body should include mission number, package type, folder path, and a note that this mission type requires manual processing. Use credential name "SMTP - Operator Notifications".
4. Set workflow id to "sentinel-manual-path" and name to "Sentinel Manual Path — B/D Handler".
5. Wire connections: trigger -> Set Manual Status -> Notify Operator.
6. The trigger node should be an Execute Sub Workflow trigger (type: `n8n-nodes-base.executeWorkflowTrigger`), NOT a webhook.

**n8n/package_router_normalizer.js** — A standalone JavaScript file containing the Code node logic for payload normalization. This will be pasted into an n8n Code node in the Package Router. The logic must:

1. Detect source: if `items[0].json.mission_id` exists, source is `ingest_sorter`; if `items[0].json.folder_name` exists and no `mission_id`, source is `folder_watcher`.
2. For folder_watcher: parse package_type from folder_name using regex `/^SAI_M(\d{4})_(.+?)_(\d{8})$/`. Extract mission_number from capture group 1 (parse to int). If regex fails, set package_type to "unknown".
3. For folder_watcher: set `needs_mission_lookup: true` (the Package Router will do a Supabase lookup for mission_id by mission_number downstream).
4. For ingest_sorter: pass through with `needs_mission_lookup: false` and `source: "ingest_sorter"`.
5. Output normalized format: `{ mission_id, mission_number, package_type, photo_count, video_count, has_ppk_data, source, needs_mission_lookup, folder_path }`.
6. Handle deduplication hint: if source is folder_watcher, set `is_fallback: true` so Package Router can check if a processing_jobs row already exists.

Do NOT hardcode email addresses. Use `{{ $env.OPERATOR_EMAIL }}` per user decision.
