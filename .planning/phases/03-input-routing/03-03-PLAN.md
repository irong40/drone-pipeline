supabase/functions/_shared/rate-limiter.ts:

Export interface RateLimitResult:
  - allowed: boolean
  - remaining: number
  - retryAfterSeconds: number | null
  - throttleMessage: string | null

Implementation:
- Use a Map<string, number[]> where key is phone number, value is array of timestamps (ms)
- Export function checkRateLimit(phone: string, options?: { maxRequests?: number, windowMs?: number }): RateLimitResult
- Defaults: maxRequests=10, windowMs=60000 (1 minute)
- On each call:
  1. Get timestamps array for phone (or empty array if new)
  2. Filter out timestamps older than windowMs from now
  3. If filtered length >= maxRequests: return { allowed: false, remaining: 0, retryAfterSeconds: Math.ceil((oldest_in_window + windowMs - now) / 1000), throttleMessage: "You're sending messages too quickly. Please wait a moment and try again." }
  4. Else: push Date.now() to array, store back, return { allowed: true, remaining: maxRequests - filtered.length - 1, retryAfterSeconds: null, throttleMessage: null }

Memory cleanup:
- Every 100 calls (use a module-level counter), sweep the Map and delete entries with no timestamps in the current window. This prevents unbounded memory growth.
- Export function resetRateLimits(): void for testing (clears the Map)

Do NOT use Node.js APIs. Pure Deno/Web standard APIs only.

Test file setup:
- Import { checkRateLimit, resetRateLimits, RateLimitResult } from rate-limiter.ts
- Call resetRateLimits() in beforeEach/setup to isolate tests
- For the "window reset" test, use a custom windowMs of 100ms and setTimeout/delay to test expiry, OR mock Date.now() by overriding it temporarily
